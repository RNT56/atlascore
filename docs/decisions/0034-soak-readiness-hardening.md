# 0034. Soak-readiness hardening: deploy-glue fixes, a scheduler dead-man's-switch, and cloud-embedding spend capping

- **Status:** Accepted
- **Date:** 2026-06-06
- **Deciders:** Operator (single-operator project)
- **Spec reference:** AtlasCore Canonical Decisions Spec v1 (date 2026-06-03), §5 (scope freeze — depth, not new sources/services), §17 (runs-unattended, single-scheduler), §20 (cost/spend cap), R16 (single-fetch guard)

## Context

The MVP (B1–B15) and the post-MVP cycle (B16–B22) are complete and the §5 freeze is in force: the next step is operational — deploy the B19 scheduler + worker on one box and let it run **unattended for a month**. A verification + readiness + risk fan-out over the as-built repo found that the *code* is ready but several gaps live in **deploy glue, runbook accuracy, and failure observability** — exactly the things that bite an operator who deploys once and walks away:

1. **DB credential mismatch.** `.env.example` shipped `DATABASE_URL=...atlas:atlas@...` while `infra/docker-compose.yml` and CI both default `POSTGRES_USER=atlascore`. A `cp .env.example .env && make dev && make migrate` failed on auth (role `atlas` never created). `.env.example` also shipped no `POSTGRES_*` block at all, so compose (which mandates `POSTGRES_PASSWORD`) needed undocumented additions.
2. **Broken systemd units.** The runbook §2.3 units `ExecStart`ed `python -m apps.scheduler` / `apps.worker --role fetch|process` — there is no `apps` package (import root is `atlascore`) and no `process` role (roles are `fetch|parse|enrich`); a verbatim copy crash-loops. No unit/timer files were shipped at all; the correct invocations existed only in the newer §6C. The backup timer template invoked `atlas backup` (local-only) instead of `infra/backup.sh` (offsite). Several recovery commands (`atlas jobs requeue/stuck/reclaim`, `atlas restore verify`, `atlas enrich backfill`) do not exist.
3. **No dead-man's-switch.** Every failure signal (stale source, deep DLQ, dead scheduler/worker/box/Postgres) was delivered *only* by the daily digest; the documented fallback was "a missing digest is itself a signal" — i.e. the operator must *notice* silence, which an unattended month does not reliably produce.
4. **Cloud embedding spend was uncapped.** `LLM_MONTHLY_SPEND_CAP_EUR` (§20) was enforced only in `enrichment/summaries/pipeline.py`; the cloud embedding backends (`enrichment/embeddings/cloud.py`) made paid calls with no ledger record and no cap check — so a cloud embedding backfill/reindex could run unmetered, despite the docs actively encouraging cloud embeddings.

All four are **depth on existing components**, not new sources/services, so they are §5-compatible.

## Decision

Ship a focused soak-readiness change:

- **Credentials.** `.env.example` gains an explicit `POSTGRES_USER/POSTGRES_PASSWORD/POSTGRES_DB` block (default `atlascore` / `change-me-local-only` / `atlascore`, matching compose + CI) and a `DATABASE_URL` whose user/password/db agree with it, with a loud "change the password before any shared deployment" note. The `core.settings` default and the integration `conftest._DEFAULT_URL` are aligned to the same `atlascore` role. `.secrets.baseline` is regenerated (pinned detect-secrets 1.5.0) for the changed placeholder.
- **Dead-man's-switch.** A new optional `HEARTBEAT_URL` (`SecretStr`, never logged) + `HEARTBEAT_TIMEOUT`. `core.heartbeat.ping_heartbeat` GETs it best-effort (never raises; logs only the exception *type* so the per-check token never leaks). `scheduler.run.run_scheduler` pings it **after each successful tick**, so a sustained outage stops the heartbeat and an external monitor (e.g. healthchecks.io) pages. Blank ⇒ disabled (`"disabled"`).
- **Embedding spend cap.** The cloud embedding backends expose `is_paid = True` + a `provider` property. `storage.embeddings.upsert_embeddings` now meters paid (`is_paid`) embeds on the **same `llm_spend` ledger and `LLM_MONTHLY_SPEND_CAP_EUR`** as summaries (`request_kind='embedding'`): it checks month-to-date spend *before* deleting/embedding and **skips** (returns 0, leaving existing vectors untouched — graceful degradation, FTS unaffected) at/over the cap; a successful paid embed records one ledger row in the caller's transaction. Local/sentence-transformers backends omit `is_paid`, so they are never metered. No schema change (the `llm_spend` row already carries `request_kind` + nullable `summary_id`).
- **Deploy glue + runbook.** Vetted unit/timer files ship under `infra/systemd/` (stack, scheduler, worker, optional parse/enrich `worker-proc@`, backup→`infra/backup.sh`, digest) with full `[Install]`/`User`/`WorkingDirectory`/`Restart`. The runbook is reconciled: §2.3 units use `atlas scheduler run` / `atlas worker run` and point at `infra/systemd/`; the backup timer invokes `infra/backup.sh` (offsite); and the non-existent `atlas jobs *` / `atlas restore verify` / `atlas enrich backfill` references are replaced with the real commands (`atlas crawl dlq`, `infra/restore_drill.sh`, `atlas reindex-embeddings`) and break-glass SQL.
- **Compose `make dev`.** `infra/docker-compose.yml` changes the off-by-default Meilisearch service's `${MEILI_MASTER_KEY:?…}` to `${MEILI_MASTER_KEY:-}` — Compose interpolates required-variable errors *before* profile filtering, so the hard `:?` broke a plain `docker compose up -d` / `make dev` for anyone not using the `search` profile. The key is now required only when that profile is actually enabled (Meilisearch enforces it at its own startup). Found by booting the real stack during verification.

## Consequences

- **Positive:** `cp .env.example .env && make dev && make migrate && make seed` works out of the box (CI-proven creds); the operator installs vetted units instead of hand-transcribing broken ones; a configured `HEARTBEAT_URL` turns "silence = undetected outage" into an active page; a cloud embedding backend can no longer run unmetered past the monthly cap; the runbook's recovery commands all exist.
- **Negative / costs:** `.env.example` ships a working-but-insecure local password (mitigated by a prominent change-me note + gitignored `.env`); the embedding cap is enforced at the persistence seam (`upsert_embeddings`) rather than inside the backend, and uses a conservative chars/4 token estimate against chat-input price rates (errs high — trips early); the heartbeat fires from the scheduler tick only (the digest timer is not separately heartbeated — a dead digest timer with a live scheduler is still only caught by reading the digest).
- **Follow-ups / obligations:** none required for the soak. Optional later depth (still §5-compatible): an `atlas crawl requeue` CLI to replace the break-glass requeue SQL; a periodic restore-drill timer; a second heartbeat on the digest path.
- **Revisit triggers:** any network-exposed or multi-source-untrusted deployment (revisit SSRF connection-pinning, ADR 0014, which remains deferred and out of scope here); running more than one fetch worker (R16 scale-up path); publishing results externally (compliance §16 household-exemption framing).
